# Документация по импорту клиентов из 1С

## Обзор

Данный модуль реализует функционал импорта клиентов из системы 1С с поддержкой синхронизации через уникальный код 1С.

## Основные возможности

1. **Уникальный код 1С** - каждое предприятие имеет уникальный идентификатор из системы 1С
2. **Синхронизация при изменении имени** - задачи сохраняются при переименовании клиента
3. **Защита от дублей** - уникальное ограничение на поле code_1c
4. **Предварительный просмотр** - модератор видит изменения перед подтверждением

## Модель данных

### Client (Клиент)

Новое поле:
```python
code_1c = models.CharField(
    _('Код 1С'),
    max_length=50,
    blank=True,
    null=True,
    unique=True,
    db_index=True,
    help_text=_('Уникальный код клиента из системы 1С.')
)
```

**Важно:** Поле `code_1c` имеет уникальное ограничение (unique=True), что предотвращает создание дублей.

## Алгоритм импорта

### Шаг 1: Загрузка файла
Модератор загружает Excel-файл со следующими столбцами:
- `id` - уникальный идентификатор (необязательно, оставьте пустым для обновления по code_1c)
- `code_1c` - код 1С (приоритетное поле для сопоставления)
- `name` - наименование клиента (обязательно)
- `address` - адрес
- `trading_point_name` - название торговой точки
- `trading_point_address` - адрес торговой точки
- `stand_count` - количество стендов
- `employee_username` - имя пользователя сотрудника

**Важно:** Поле `code_1c` должно быть вторым столбцом (после `id`) для корректного импорта.

### Шаг 2: Идентификация клиентов

Программа проверяет каждую строку файла:

#### Приоритет 1: Поиск по коду 1С
```
Если code_1c заполнен:
  → Ищем клиента в базе по code_1c
  → Если найден:
    - Обновляем имя (если отличается)
    - Обновляем другие поля из файла
    - Задачи сохраняются за клиентом
  → Если не найден:
    - Пропускаем запись (не создаем нового)
```

#### Приоритет 2: Поиск по наименованию
```
Если code_1c пуст:
  → Ищем клиента в базе по name (точное совпадение)
  → Если найден:
    - Добавляем code_1c (если предоставлен и поле пустое)
    - Обновляем другие поля
    - Задачи сохраняются
  → Если не найден:
    - Пропускаем запись
```

### Шаг 3: Предварительный просмотр

Модератор видит:
- Список клиентов для обновления
- Какие поля будут изменены
- Список пропущенных записей (без совпадений)
- Предупреждения о возможных дублях

### Шаг 4: Подтверждение импорта

После подтверждения:
- Все изменения применяются
- Задачи остаются закрепленными за клиентами
- История изменений сохраняется

## Сценарии использования

### Сценарий 1: Обновление имени по коду 1С

**До импорта:**
- Клиент: `ООО "Старое Название"`
- Код 1С: `1C-001`
- Задачи: 5

**Файл импорта:**
- name: `ООО "Новое Название"`
- code_1c: `1C-001`

**После импорта:**
- Клиент: `ООО "Новое Название"`
- Код 1С: `1C-001` (не изменился)
- Задачи: 5 (сохранены)

### Сценарий 2: Добавление кода 1С к существующему клиенту

**До импорта:**
- Клиент: `ООО "Вектор"`
- Код 1С: `null`
- Задачи: 3

**Файл импорта:**
- name: `ООО "Вектор"`
- code_1c: `1C-004`

**После импорта:**
- Клиент: `ООО "Вектор"`
- Код 1С: `1C-004` (добавлен)
- Задачи: 3 (сохранены)

### Сценарий 3: Клиент без совпадений

**Файл импорта:**
- name: `ООО "Гамма"` (нет в базе)
- code_1c: `null` (нет совпадения)

**Результат:**
- Запись пропускается
- Новый клиент не создается
- Требуется ручное создание через админку

### Сценарий 4: Защита от дублей

**Попытка импорта:**
- name: `ООО "Альфа"`
- code_1c: `1C-003` (уже существует)

**Результат:**
- Существующий клиент обновляется
- Дубль не создается (уникальное ограничение)

## Технические детали

### База данных

- Поле `code_1c` имеет индекс для быстрого поиска
- Уникальное ограничение на уровне БД
- Поддержка NULL значений

### Валидация

- Проверка уникальности перед сохранением
- Очистка поля name от лишних символов
- Обработка специальных символов в Excel

### Производительность

- Пакетная обработка записей
- Оптимизированные SQL-запросы
- Кэширование результатов поиска

## Безопасность

- Только модераторы могут импортировать клиентов
- CSRF-защита форм
- Валидация загружаемых файлов
- Транзакционность операций

## Известные ограничения

1. **Точное совпадение имен** - поиск по имени требует точного совпадения (с учетом регистра)
2. **Нет создания новых клиентов** - импорт только обновляет существующие записи
3. **Один файл за раз** - массовая загрузка нескольких файлов не поддерживается
